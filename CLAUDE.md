# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Fallen Haven is a full-stack turn-based strategy game running on Cloudflare Workers. It is a **single-package monorepo** — one `package.json` at the root, one `wrangler.jsonc`, one Vite config. The Worker serves both the API and the static frontend assets.

## Commands

```bash
npm run dev          # Start Vite dev server (runs Worker + frontend together via @cloudflare/vite-plugin)
npm run build        # Vite build → dist/ (client assets + worker bundle)
npm run deploy       # Build then wrangler deploy (one step: Worker + static assets)
npm test             # Vitest (worker, client, and shared test suites)
npm run cf-typegen   # Regenerate worker-configuration.d.ts from wrangler.jsonc — run after changing bindings
npm run generate:data # Recompile Flatbuffers schemas + regenerate provinces.bin
npm run lint         # ESLint
npm run format       # Prettier
```

Run a single test:
```bash
npx vitest run src/my-file.spec.ts
npx vitest run --reporter=verbose
```

### API routes

All API routes are prefixed with `/api/`. All other requests fall through to static assets (`ASSETS` binding).

```
GET  /api/version
GET  /api/games          # list games for the current user
POST /api/games          # create game (body: CreateRequest)
GET  /api/games/:id      # show game (filtered by removeUnknown)
POST /api/games/:id/player  # join as second player
POST /api/games/:id/ws   # mint a WebSocket token
GET  /api/games/:id/ws?token=  # upgrade to WebSocket
```

### Worker bindings (`Env` interface)

Generated by `wrangler types` from `wrangler.jsonc`. Never edit `worker-configuration.d.ts` by hand.

| Binding | Type | Purpose |
|---|---|---|
| `ASSETS` | `Fetcher` | Serves Vite-built static files |
| `GAME` | `DurableObjectNamespace<Game>` | Stateful game instances |
| `DEV` | `string` | `"true"` in `.dev.vars` — enables Bearer auth bypass in dev |

### Authentication

**Production**: Cloudflare Access sits in front of the Worker. After login, CF injects `CF-Access-Jwt-Assertion` header containing a signed JWT. The Worker verifies it against `https://jasoncabot.cloudflareaccess.com/cdn-cgi/access/certs` using audience tag `4020d7da2260214f3972a347977866c2795d9a264a718a055a131d935f5a42c9`. The `sub` claim becomes the `userId`.

**Development**: Set `DEV=true` in `.dev.vars`. The Worker then accepts `Authorization: Bearer <uuid>`. The client sends this header automatically when `import.meta.env.DEV` is true (see `client/models/API.ts`). Copy `.dev.vars.example` to `.dev.vars` to get started.

### Hono patterns

- `HonoEnv` type in `src/middleware/auth.ts` carries `Bindings: Env` and `Variables: { userId: string }`
- Routes get the typed user via `c.get('userId')` after `requireUser` middleware
- Bindings via `c.env.GAME`, `c.env.ASSETS`
- Worker entry exports `default app` — Hono's `app.fetch` is the Worker handler
- Static asset fallback: `app.all('*', (c) => c.env.ASSETS.fetch(c.req.raw))`

### Durable Objects

`Game` class in `src/durable-objects/game.ts`. Uses URL-encoded action routing internally (e.g. `https://game?action=create&id=...`). Each game instance stores the full `GameState` JSON keyed by userId. A shared `users` DO instance stores the game list for all users.

Key exports from the DO file: `buildGameListId`, `createGameAction`, `showGameAction`, etc. — used by `src/routes/games.ts`.

### Shared code

`shared/` is plain TypeScript — no package.json, no build step. Both `src/` (worker) and `client/` import from it via the `@shared/*` path alias configured in `vite.config.ts` and both tsconfigs.

Key types:
- `GameState` — full game state stored in the DO
- `PlayerGameProjection` — filtered view returned to the client
- `ProvinceState` — province data including units, structures, walls, roads
- `Alliance` — `'HUMAN' | 'ALIEN' | 'NEUTRAL'`
- `UnitData` / `StructureData` — reference data dictionaries keyed by category code (e.g. `'HSQU'`)

### Flatbuffers data

Province geography (`shared/data/provinces.bin`) is generated from `shared/generate.ts` using Flatbuffers schemas in `flatbuffers/`. Only re-run `npm run generate:data` when province topology changes. The binary is committed to git.

`vite.config.ts` includes a `binaryPlugin` that loads `.bin` files as `Uint8Array` at build time (mirrors esbuild's `loader: { ".bin": "binary" }`).

### Styling

Tailwind v4 via `@tailwindcss/vite`. Import entry: `client/main.css` contains `@import "tailwindcss"`. No `tailwind.config.js` needed. Use utility classes in TSX/HTML directly.

### TypeScript split

| Config | Covers | Notes |
|---|---|---|
| `tsconfig.json` | `src/`, `shared/` | No DOM; uses workerd runtime types from `worker-configuration.d.ts` |
| `tsconfig.client.json` | `client/`, `shared/` | Adds DOM lib + JSX; no workers-types |

### Tests

Three Vitest projects in `vitest.config.ts`:
- **worker** (`src/**/*.spec.ts`) — runs in real workerd via `@cloudflare/vitest-pool-workers`, reads `wrangler.jsonc` for bindings
- **client** (`client/**/*.spec.tsx`) — `happy-dom` environment
- **shared** (`shared/**/*.spec.ts`) — plain Node

### Deployment

Configured via Cloudflare dashboard (automatic deployments on push to `main`). Manual deploy: `npm run deploy` (builds first, then `wrangler deploy`). The `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are set in the CF dashboard, not in this repo.
